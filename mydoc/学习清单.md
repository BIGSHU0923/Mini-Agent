## 0. 给 Java 开发者的 Python 速览（先读这一节）

你写 Java 的习惯不能直接套过来，先记住这几个关键差异：

| Java 概念 | Python 对应物 | 说明 |
|---|---|---|
| `Maven` / `Gradle` | `pyproject.toml` + `uv` | 本项目用 **uv** 管理依赖（见 [pyproject.toml](file:///d:/project/mini-agent/Mini-Agent/pyproject.toml)） |
| `pom.xml` 里的 `dependency` | `[project] dependencies` | 依赖清单在 `pyproject.toml` 第 11-25 行 |
| `target/` / 本地 m2 仓库 | `.venv/`（虚拟环境） | **每个项目一个独立环境**，依赖装在 `.venv\Scripts\` 下 |
| `package com.foo;` 目录结构 | 普通目录 + `__init__.py` | `mini_agent/` 就是包名 |
| `java -jar xxx.jar` | `python -m 包名.模块` | 例如 `python -m mini_agent.cli` |
| `public static void main` | 入口函数 + `if __name__ == "__main__":` | 见 [cli.py](file:///d:/project/mini-agent/Mini-Agent/mini_agent/cli.py) 末尾 |
| `interface` / `@Override` | 抽象基类 / 继承 | `class Agent:` 就是普通类，`Tool` 是抽象基类 |
| `List<Message>` / `Map` | `list` / `dict` | 见 [schema.py](file:///d:/project/mini-agent/Mini-Agent/mini_agent/schema/schema.py) |
| DTO / POJO | `pydantic.BaseModel` | 自带校验与序列化，比 Lombok 更强 |
| `CompletableFuture` | `async def` + `await` | 本项目 LLM 调用全是异步的（asyncio） |

**最重要的一点**：Python 项目不用编译，改完代码直接运行即可（没有 `mvn compile` 这一步）。

当前你的环境（我已确认）：
- Python **3.11.9**（项目要求 >= 3.10，✅ 满足）
- uv **0.13.8** 已安装
- `.venv` 已存在且依赖已装好
- [config.yaml](file:///d:/project/mini-agent/Mini-Agent/mini_agent/config/config.yaml) 已存在且已填好 API Key

也就是说：**你现在可以直接跳到第 1 节运行，无需再做任何安装。**

## 1. 如何启动（重点）

### 1.1 先理解「为什么启动方式这么多」

Java 里启动很统一：`java -jar`。Python 项目常见 3 种启动方式，本项目三种都支持：

| 方式 | 命令 | 适用场景 |
|---|---|---|
| ① 模块方式 | `python -m mini_agent.cli` | **调试首选**，最直观 |
| ② uv 运行 | `uv run python -m mini_agent.cli` | 官方推荐，自动用 `.venv` |
| ③ 安装成命令 | `mini-agent` | 装完可全局调用 |

> ⚠️ 注意：README 里提到的 `pip install -r requirements.txt` 在**本仓库并不存在该文件**（根目录没有 `requirements.txt`），请以 `pyproject.toml` 为准，用 `uv sync` 安装依赖。

### 1.2 第一步：确认你在项目根目录

所有命令都必须在项目根目录执行，否则会报 `ModuleNotFoundError`。

```powershell
cd d:\project\mini-agent\Mini-Agent
```

### 1.3 第二步：安装/同步依赖（如果换了电脑或依赖缺失才需要）

```powershell
uv sync
```

- `uv sync` 相当于 `mvn dependency:resolve`，会读取 `pyproject.toml` + `uv.lock`，把依赖装进 `.venv`。
- 你的机器上依赖已装好，**跳过这步也能跑**。

### 1.4 第三步：确认配置文件（关键，否则启动会退出）

程序启动时会按优先级找 `config.yaml`：
1. `mini_agent/config/config.yaml`（开发模式，**你现在的就是这里**）
2. `~/.mini-agent/config/config.yaml`（用户目录）
3. 包安装目录

不出所料的话，直接看这个文件，确认里面 `api_key` 不是 `YOUR_API_KEY_HERE`：

```powershell
# 查看配置（在项目根目录执行）
Get-Content mini_agent\config\config.yaml
```

如果你要自己重新配置（例如换 API Key），复制模板再改：

```powershell
Copy-Item mini_agent\config\config-example.yaml mini_agent\config\config.yaml
notepad mini_agent\config\config.yaml
```

需要关注的几个字段（见 [config-example.yaml](file:///d:/project/mini-agent/Mini-Agent/mini_agent/config/config-example.yaml)）：

```yaml
api_key: "你的Key"
api_base: "https://api.minimaxi.com"   # 国内版；海外版用 https://api.minimax.io
model: "MiniMax-M2.5"
provider: "anthropic"                   # 或 "openai"
max_steps: 100                          # Agent 最大循环步数
```

### 1.5 第四步：正式启动（三选一）

#### 方式 A：交互式 CLI（像聊天一样用）

```powershell
uv run python -m mini_agent.cli
```

或（如果 `.venv` 已激活）直接：

```powershell
python -m mini_agent.cli
```

启动后你会看到欢迎横幅，然后输入任务即可。常用命令：

| 命令 | 作用 |
|---|---|
| 直接输入文字 | 给 Agent 下达任务 |
| `/help` | 查看帮助 |
| `/clear` | 清空当前会话历史 |
| `/history` | 查看消息条数 |
| `/stats` | 查看本次会话统计（耗时、token、消息数） |
| `/log` | 显示日志目录 |
| `/exit` | 退出 |
| `Esc` | **中断当前正在执行的任务** |

#### 方式 B：单次任务模式（非交互，**调试强烈推荐**）

```powershell
uv run python -m mini_agent.cli --task "在 workspace 下创建一个 hello.txt，内容写 hello world"
```

执行完自动退出并打印统计信息。**为什么推荐调试用这个**：交互模式用了 `prompt_toolkit`，和调试器/断点配合会有卡顿问题；`--task` 模式是纯线性流程，断点最好用。

#### 方式 C：安装为全局命令

```powershell
uv tool install -e .
mini-agent                       # 之后可在任意目录运行
mini-agent --workspace d:\some\dir
mini-agent --task "xxx"
mini-agent --version
mini-agent log                    # 查看日志目录
```

> `-e` 是 editable（可编辑安装），相当于 Java 里把源码目录挂进 classpath，改代码立即生效，无需重装。

### 1.6 第五步：跑官方示例（最适合零基础入手）

示例从简单到复杂排列，见 [examples/README_CN.md](file:///d:/project/mini-agent/Mini-Agent/examples/README_CN.md)：

```powershell
# 示例 1：纯工具调用，不需要 API Key，最适合第一次跑
uv run python examples\01_basic_tools.py

# 示例 2：最简单的 Agent（需要 API Key）
uv run python examples\02_simple_agent.py

# 示例 3：会话记忆
uv run python examples\03_session_notes.py

# 示例 4：完整功能（工具 + 记忆 + MCP）
uv run python examples\04_full_agent.py
```

### 1.7 一次完整启动演示（照着敲即可）

```powershell
cd d:\project\mini-agent\Mini-Agent
uv sync                                                  # 第1步：同步依赖（可跳过）
Get-Content mini_agent\config\config.yaml | Select-String api_key   # 第2步：确认Key
uv run python examples\01_basic_tools.py                 # 第3步：先跑免Key示例
uv run python -m mini_agent.cli --task "创建 hello.txt"  # 第4步：跑一个真实任务
uv run python -m mini_agent.cli                          # 第5步：进入交互模式体验
```

## 2. 如何调试（重点）

Python 的调试比 Java 更简单：**不用配置远程调试端口，直接在 IDE 里点小球打断点就能跑**。下面按「从易到难」给你四种手段。

### 2.1 手段一：断点调试（最常用，强烈推荐）

项目自带一个 VS Code / Trae 通用的调试配置思路。在项目根目录新建 `.vscode\launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "调试：单次任务(cli --task)",
      "type": "debugpy",
      "request": "launch",
      "module": "mini_agent.cli",
      "args": ["--task", "在 workspace 下创建 hello.txt，内容为 hello world"],
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "justMyCode": false
    },
    {
      "name": "调试：交互式 CLI",
      "type": "debugpy",
      "request": "launch",
      "module": "mini_agent.cli",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "justMyCode": false
    },
    {
      "name": "调试：当前打开的示例文件",
      "type": "debugpy",
      "request": "launch",
      "program": "${file}",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "justMyCode": false
    },
    {
      "name": "调试：当前测试文件",
      "type": "debugpy",
      "request": "launch",
      "module": "pytest",
      "args": ["${file}", "-v"],
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}",
      "justMyCode": false
    }
  ]
}
```

**使用步骤：**
1. 在 [agent.py](file:///d:/project/mini-agent/Mini-Agent/mini_agent/agent.py) 的 `run()` 方法里，点代码行号左边打个红点（断点），比如打在 `response = await self.llm.generate(...)` 那一行。
2. 左侧「运行和调试」面板里选择 **`调试：单次任务(cli --task)`**。
3. 按 `F5` 启动。程序会停在断点处。
4. 此时你可以：
   - 鼠标悬停变量看值（如 `self.messages`）
   - 左侧「变量」面板展开看 `self.messages`、`self.tools`、`response`
   - 用「调试控制台」直接敲表达式，例如 `len(self.messages)`、`self.tools.keys()`
   - `F10` 单步跳过、`F11` 单步进入、`F5` 继续

> 关键参数解释：
> - `justMyCode: false` → 允许进入第三方库源码（学习时有用，能看到 mcp/anthropic 内部）
> - `module: "mini_agent.cli"` → 等价于命令行 `python -m mini_agent.cli`
> - `console: "integratedTerminal"` → 交互式输入需要真实终端

### 2.2 手段二：调试测试用例（读懂行为最快的路）

项目的测试写得很好，**调试测试比读文档还快**，因为每个测试就是一个小场景。

```powershell
# 命令行运行全部测试
uv run pytest tests\ -v

# 只跑 Agent 相关测试
uv run pytest tests\test_agent.py -v

# 跑单个测试函数
uv run pytest tests\test_agent.py::test_xxx -v
```

在 IDE 里：直接用上面的「调试：当前测试文件」配置，对着 [tests/test_agent.py](file:///d:/project/mini-agent/Mini-Agent/tests/test_agent.py) 打断点即可。

### 2.3 手段三：日志文件（排查「模型到底发了什么」）

这是本项目的宝藏功能。每运行一次，终端都会打印一行：

```
📝 Log file: C:\Users\xxx\.mini-agent\log\agent_run_xxx.log
```

打开这个日志文件，你会看到**每一步发给大模型的完整 JSON 和模型返回的完整 JSON**。当你想搞清楚「Agent 为什么调用了某个工具」时，看日志比看代码还直接。

```powershell
# 查看日志目录里最新的日志
Get-ChildItem $env:USERPROFILE\.mini-agent\log | Sort-Object LastWriteTime -Descending | Select-Object -First 3
```

日志记录逻辑在 [logger.py](file:///d:/project/mini-agent/Mini-Agent/mini_agent/logger.py)，感兴趣可以一并读。

### 2.4 手段四：pdb 命令行调试（不依赖 IDE）

如果你只想在终端里快速调试，可以在代码里插一行：

```python
breakpoint()   # 程序运行到这里会暂停，进入交互式调试
```

运行后可用命令：
- `p self.messages` 打印变量
- `n` 下一行 / `s` 进入函数 / `c` 继续
- `q` 退出

> 调试完记得删掉 `breakpoint()`。这是临时手段，日常还是用 IDE 断点。

### 2.5 调试常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'mini_agent'` | 不在项目根目录运行 | `cd` 到项目根目录再运行 |
| 启动后立刻退出，提示找不到 config | 配置文件缺失/路径不对 | 确认 `mini_agent\config\config.yaml` 存在 |
| 提示 `Please configure a valid API Key` | api_key 还是占位符 | 编辑 config.yaml 填真实 Key |
| 断点不停 / 提示未验证断点 | 装错解释器 | 在 IDE 右下角选择 `.venv` 里的 Python 作为解释器 |
| 交互模式断点卡住 | prompt_toolkit 与调试器冲突 | 改用 `--task` 模式调试 |
| `SSL: CERTIFICATE_VERIFY_FAILED` | 公司代理/证书问题 | 见 README「常见问题」章节 |

**关于「选对解释器」**（Java 里没这个概念，最容易踩坑）：
IDE 需要知道用哪个 Python 运行。确保选的是项目里的 `.venv`：
- VS Code / Trae：`Ctrl+Shift+P` → 输入 `Python: Select Interpreter` → 选择 `.\venv\Scripts\python.exe`
- 选对之后，IDE 才有代码跳转、补全和断点能力。
